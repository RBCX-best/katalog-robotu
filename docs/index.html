Jak přidat robota do katalogu?

Celý katalog funguje plně automatizovaně prostřednictvím nového webového formuláře a GitHub Actions.

1

Vyplňte formulář

Klikněte na tlačítko níže a zadejte všechny údaje o vašem robotovi a jeho hardware.

2

Nahrajte fotku

Formulář vás přesměruje na GitHub. Přetáhněte do textového pole fotografii a vytvořte Issue.

3

Schválení

Vedoucí kroužku zkontroluje nahrané informace a k danému Issue přidá štítek schvaleno.

4

Automatický web

Akce stáhne fotku, aktualizuje JSON, issue označí jako zpracovano a web se ihned překreslí!

Návody & Kodex kroužku

Vše, co potřebuješ vědět pro správné zdokumentování a sdílení svého projektu.

Návod 1 Jak správně založit repozitář na GitHubu
  1. 1
    Přejdi na GitHub organizaci kroužku a klikni na zelené tlačítko New repository.
  2. 2
    Pojmenuj repozitář jasně: například robot-nazev-rok. Nastav viditelnost na Public.
  3. 3
    Zaškrtni "Add a README file" — tím se repo ihned inicializuje a máš kam psát popis projektu.
  4. 4
    Přidej .gitignore šablonu odpovídající tvému projektu:
    • Arduino / C++: zvol šablonu C++ nebo Arduino
    • Python: zvol šablonu Python
  5. 5
    Klikni "Create repository" — hotovo! Teď si repo naklonuj na svůj počítač příkazem git clone URL.

Repozitář dej vždy pod organizaci kroužku, ne pod svůj osobní profil — jinak k němu ostatní nebudou mít přístup.

Návod 2 Základní práce s Gitem (Git Cheatsheet)

Tyhle čtyři příkazy používáš úplně pokaždé. Nauč se je nazpaměť!

git pull origin main

⬇️ Stáhni si nejnovější verzi od ostatních členů kroužku. Dělej to vždy jako první věc, než začneš pracovat.

git add .

📦 Připrav všechny změněné soubory k uložení. Tečka znamená "všechno v aktuální složce".

git commit -m "popis změn"

💾 Ulož změny s popisem. Piš krátce, ale jasně — co jsi změnil? Např. "přidán senzor vzdálenosti na pin 5".

git push origin main

🚀 Pošli změny na GitHub. Teprve po tomhle příkazu ostatní uvidí tvou práci.

Pro pokročilé — větve

git branch moje-nova-funkce git checkout moje-nova-funkce

🌿 Vlastní větev ti umožní experimentovat bez rizika, že "rozbije" fungující kód ostatních. Až budeš spokojený, větev mergneš do main.

Zlaté pravidlo: vždy nejdřív git pull, pak pracuj, pak git add → commit → push. Ušetříš si hodiny řešení konfliktů.

Návod 3 Standard dokumentace: README.md a fotky

Dobrý README je jako technický průkaz robota — kdokoli ho otevře a okamžitě ví, co robot dělá a jak je zapojen.

README musí obsahovat:

  • Stručný popis robota — co dělá, na jakou soutěž byl postaven, kdo ho vyrobil.
  • Seznam pinů a zapojení — tabulka nebo schéma, co je připojeno kam.
  • Hlavní fotografie robota — tu samou, kterou nahraješ i do katalogu přes Issue.
Klíčové doporučení kroužku

Důrazně doporučujeme do README nahrávat detailní fotky zapojení kabelů a elektroniky! Když se robot po půl roce rozbije, bez fotky zapojení ho nikdo nedá dohromady.

Návod 4 Mechanický design a 3D modely (CAD/SolidWorks)

Elektronika je jen polovina robota. Mechanika a 3D tisk jsou stejně důležité — a stejně tak potřebují zálohu.

Soubory k tisku

Nahrávej finální soubory pro 3D tiskárnu:

.stl .step .3mf
Zdrojové soubory sestav

Nahrávej i editovatelné zdrojáky pro CAD:

.sldprt .sldasm .f3d

Proč to dělat?

Díky nahraným souborům bude mít kdokoli v budoucnu možnost si poškozenou součástku robota znovu vytisknout nebo upravit — i bez tebe, i za tři roky. Tiskárna v kroužku stojí, 3D modely bez zdrojáků jsou k ničemu.

Doporučená struktura složek v repozitáři

📁 robot-nazev/
├── 📁 firmware/        ← kód pro mikrokontrolér
├── 📁 cad/
│   ├── 📁 step/        ← .step / .stl pro tisk
│   └── 📁 source/      ← .sldprt, .sldasm, .f3d
├── 📁 docs/
│   └── 📁 photos/      ← fotky zapojení + robot
└── README.md
